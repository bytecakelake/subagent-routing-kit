# 서브에이전트 작업 계약

- task_id / run_id:
- 목적: 한 문장으로 검증 가능한 결과
- 경로: 현재 위임 도구에 등록된 정확한 경로 이름
- 티어 / 선택 이유 / 입력 규모:
- 선행 작업: 없거나 이미 반환·검증된 task_id
- 제공 사실·인터페이스·정확한 식별자:
- 먼저 읽을 brief / 원문 / 자료:
- 읽기 범위:
- 쓰기 범위: 정확한 파일 또는 없음
- 금지: 재위임·범위 밖 쓰기·비밀 접근·외부 게시·자동 commit/push 등 작업에 맞게 명시
- 도구/검사: 현재 사용 가능한 도구와 실행 가능한 검사 명령
- 인수 기준: 체크 가능한 목록
- 자원 목표: 도구 호출/시간/재시도 목표. hard cap 아님을 명시
- 종료: 기준 충족, 근거 부족, 권한/환경 blocker, 할당 범위 소진 중 하나
- 보고: status, 핵심 결과, evidence, artifact 경로, tests/checks, unresolved, scope_changes
- 불명확한 요구는 추측 변경하지 말고 blocker와 최소 필요 정보를 반환

## 부모 확인

- 경로가 실제 등록되어 있는가? 도구가 받지 않는 작업별 인자를 만들지 않았는가?
- 형제의 산출물 없이 실행 가능한가? 공유 쓰기가 충돌하지 않는가?
- 자식의 상태가 아니라 실제 근거를 확인할 방법이 있는가?

## 최소 출력 계약 예

```json
{
  "status": "completed|partial|blocked",
  "result": "짧은 요약",
  "evidence": [{"path_or_url": "정확한 경로/URL", "check": "확인한 내용"}],
  "artifacts": [],
  "checks": [],
  "unresolved": []
}
```

이는 출력 형식 예시다. 출력 스키마를 쓴다면 부모가 실제 읽는 필드만 필수화하고 enum/status와 근거의 사실성은 별도로 검증한다.
